# DailyBrief US: автоматический новостной сайт

Каждые 30 минут сайт сам:
1. забирает свежие новости из RSS-лент американских изданий (NPR, BBC US, TechCrunch, NASA, ESPN, список можно менять);
2. отдаёт ИИ **только заголовок и короткую аннотацию** из ленты, и ИИ пишет собственный пересказ на английском (2–3 абзаца) плюс блок «Context»;
3. **автоматически проверяет текст на совпадения с источником**: если совпадает 6+ слов подряд в заметной доле текста или 10+ слов подряд где угодно, текст переписывается заново, а при повторной неудаче не публикуется;
4. пересобирает статический сайт: HTML и один CSS-файл на 3 КБ, без JavaScript и без чужих картинок. Страница статьи весит ~4–5 КБ;
5. удаляет материалы старше 30 дней, поэтому сайт не разрастается.

Сервер не нужен: всё работает бесплатно на GitHub Actions + GitHub Pages или Cloudflare Pages.

## Чем это отличается от dayoff.news (с точки зрения авторского права)

| | dayoff.news | этот движок |
|---|---|---|
| Текст статьи | копирует ~2 абзаца оригинала дословно | ни одного абзаца оригинала, только свой пересказ |
| Картинки | hotlink фото издания (часто Getty Images) | чужих картинок нет совсем |
| Проверка заимствований | нет | автоматическая, на каждой статье |
| Источник и ссылка | есть | есть, крупная кнопка «Read the original» |
| Страница для правообладателей / DMCA | нет | есть (`/rights/`) + чёрный список источников в конфиге |

Почему так: авторское право охраняет **форму изложения**, а не сами факты. Это прямо закреплено в Бернской конвенции (ст. 2(8): новости дня и сообщения о фактах не охраняются) и в законе США (17 U.S.C. § 102(b)). Пересказ фактов своими словами со ссылкой на источник — то, чем легально занимаются агрегаторы. Фотографии, наоборот, охраняются всегда, и именно за них чаще всего прилетают претензии (Getty рассылает требования о компенсации). Поэтому фото здесь нет.

## Запуск за ~20 минут

1. Создайте репозиторий на GitHub и загрузите туда содержимое этой папки.
2. **Settings → Secrets and variables → Actions → New secret**: `ANTHROPIC_API_KEY` = ваш ключ с console.anthropic.com. Подойдёт и OpenAI-совместимый API: в `config.json` поставьте `"provider": "openai"`, нужную модель, `api_key_env` и `openai_base_url`.
3. **Settings → Pages → Source: GitHub Actions**.
4. В `config.json` пропишите `base_url` (адрес сайта), название, `contact_email`.
5. **Actions → Build news site → Run workflow**. Через пару минут сайт появится, дальше обновляется сам.

Локальная проверка без ключа и без сети: `python build.py --mock --feeds-dir samples`, затем `cd public && python -m http.server`.

## Реклама

В `config.json`, раздел `ads`:
- `head_code` — скрипт рекламной сети (например, код Google AdSense из `<head>`);
- `ads_txt` — строка для файла `ads.txt` (AdSense её выдаёт; без неё доход режется);
- `slots` — HTML-код для каждого места: `header`, `in_feed` (в ленте после каждой 6-й карточки, настраивается `every_n_cards`), `article_middle` (между абзацами), `article_bottom`, `footer`.

Пока код слота пустой, на его месте видна пунктирная заглушка «AD · …», так вы видите разметку. Блок над текстом статьи я убрал намеренно: Google понижает страницы, где реклама на первом экране вытесняет контент. Страница `/privacy/` с обязательными для AdSense пунктами о cookie уже есть.

## Google Search Console

1. search.google.com/search-console → добавить ресурс → «Префикс URL» → способ «HTML-тег».
2. Значение из `content="..."` вставьте в `config.json` → `google_site_verification`, дождитесь сборки, нажмите «Подтвердить».
3. Отправьте sitemap: `https://ваш-сайт/sitemap.xml` (генерируется автоматически при каждой сборке).

Каждая статья размечена Schema.org `NewsArticle` со ссылкой на первоисточник (`isBasedOn`).

## Показ только в США

На GitHub Pages ограничить доступ по странам нельзя. Нужен Cloudflare (бесплатный план):
1. Домен (≈$10/год) → подключить к Cloudflare.
2. В `.github/workflows/build.yml` переключиться на «Вариант Б» (Cloudflare Pages), добавить секреты `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID`.
3. Cloudflare → Security → WAF → Custom rules → Create rule → Edit expression:
   ```
   (ip.geoip.country ne "US" and not cf.client.bot)
   ```
   Action: **Block** (или Managed Challenge).
   `not cf.client.bot` обязателен: без него можно заблокировать Googlebot и проверяющих AdSense, и сайт выпадет из поиска.

Учтите: сами вы из Азербайджана тоже не увидите сайт. Добавьте в правило исключение для своего IP: `and ip.src ne ВАШ_IP`.

Для поиска отдельная «привязка к стране» не нужна (Google убрал эту настройку из Search Console). Таргетинг на США задаётся английским языком, американскими источниками и темами.

## Важные риски (прочитайте)

- **Политика Google против «масштабного контента» (scaled content abuse).** Google понижает или исключает из индекса сайты, массово публикующие автоматически сгенерированные страницы без добавленной ценности. Сайт с ИИ-пересказами под этот риск попадает, независимо от авторского права. AdSense такие сайты тоже часто не одобряет («low value content»). Что помогает:
  - не публиковать слишком много: `max_new_per_run` = 5–10 вместо 25;
  - держать узкую тематику (например, только технологии или только спорт), а не «всё подряд»;
  - добавлять руками хотя бы несколько собственных материалов в неделю;
  - на первые месяцы взять только 2–3 сильных источника.
- **Ошибки ИИ.** Пересказ может исказить факт. На каждой странице есть пометка, что текст сгенерирован автоматически, но за неточности, особенно о реальных людях, отвечает владелец сайта. Новости о преступлениях и обвинениях — зона повышенного риска (диффамация).
- **Условия использования лент.** Большинство RSS-лент разрешают некоммерческое использование заголовков со ссылкой. При рекламной монетизации проверьте Terms of Use каждого источника. Неподходящий источник просто уберите из `sources`.
- **При жалобе** добавьте источник в `blocked_sources` или конкретную ссылку в `blocked_urls`: при следующей сборке материалы исчезнут.

Это технический и общий правовой обзор, а не юридическая консультация.

## Структура

```
config.json            — все настройки: сайт, источники, реклама, ИИ
build.py               — один запуск = сбор → пересказ → сборка
engine/fetch.py        — чтение RSS/Atom (с ETag, чтобы не грузить лишнее)
engine/rewrite.py      — промпт и вызов ИИ (Anthropic или OpenAI-совместимый)
engine/originality.py  — проверка на заимствования
engine/render.py       — HTML-шаблоны, sitemap, RSS, ads.txt
assets/style.css       — оформление (светлая/тёмная тема)
data/                  — база статей (обновляется автоматически)
.github/workflows/     — расписание запуска
```
